# Nginx实战：反向代理、负载均衡与静态服务

Nginx是全世界使用最广泛的Web服务器。超过三分之一的网站用Nginx做反向代理和负载均衡。它做静态文件服务快得惊人，做反向代理配置灵活，做负载均衡能轻松扛住几万并发。但很多人对Nginx的印象还停留在"改改配置文件转发一下请求"，没有真正用起来它的强大功能。

## 一、Nginx是什么

Nginx是一个高性能的HTTP服务器和反向代理服务器。它最初就是为了解决C10K问题（单台服务器同时处理一万个并发连接）而设计的。采用事件驱动的异步非阻塞架构，内存占用小、并发能力强。

Nginx有两个核心角色：作为Web服务器直接提供静态文件；作为反向代理把请求转发给后端应用服务器。

## 二、反向代理：请求的统一入口

反向代理是Nginx最常用的功能。用户不直接访问后端应用，而是访问Nginx，Nginx根据规则把请求转发给后端的某个服务。

最简单的配置： server { listen 80; server_name example.com; location / { proxy_pass http://127.0.0.1:3000; } }

所有发往example.com的请求，都转发到本机3000端口的Node.js服务。用户不知道后端跑的是什么、跑在几台机器上。

反向代理的好处：安全——后端应用不直接暴露公网，只监听本地端口，外部只能通过Nginx访问。统一入口——SSL终止、日志记录、访问控制都在Nginx层做，后端应用不用管。

## 三、负载均衡：把流量分给多台服务器

当一台服务器扛不住流量了，就加几台，Nginx在前面做负载均衡，把请求平均分到多台后端服务器。

upstream backend { server 192.168.1.1:3000; server 192.168.1.2:3000; server 192.168.1.3:3000; } server { location / { proxy_pass http://backend; } }

默认是轮询——请求一个一个轮流分给三台服务器。还可以配置权重（某台机器性能好多分点流量）、ip_hash（同一个用户固定访问同一台服务器，解决Session共享问题）。

## 四、静态文件服务

Nginx做静态文件服务的性能极高，直接从磁盘读文件返回，不需要经过后端应用。

server { root /var/www/dist; location / { try_files $uri $uri/ /index.html; } }

把前端构建产物放在/var/www/dist目录，Nginx直接对外提供访问。try_files那行是SPA（单页应用）的关键：先找文件，找不到就返回index.html，让前端路由处理。

## 五、HTTPS与Gzip

Nginx配置HTTPS非常简单：把证书文件路径配上，listen 443 ssl就行。HTTP的80端口自动301跳转到HTTPS。

Gzip压缩也是Nginx一行配置开启的：gzip on;。开启后，文本类资源（HTML、CSS、JS）会被压缩传输，体积缩小70%以上，加载速度大幅提升。

## 六、常用Location匹配

location /匹配所有路径。 location /api/匹配以/api/开头的路径。 location ~ \.js$用正则匹配以.js结尾的请求。 = /精确匹配根路径。

掌握这几种匹配方式，就能灵活地把不同路径的请求分发到不同的后端或者处理方式。

## 七、总结

Nginx不是什么复杂的技术，但它是每个Web项目都要用到的基础设施。反向代理、负载均衡、静态服务、HTTPS终止、Gzip压缩——这些是Nginx最常用的功能。配置文件写多了就发现，它就是一套声明式规则，理解了location匹配和proxy_pass的转发逻辑，大部分场景都能搞定。
